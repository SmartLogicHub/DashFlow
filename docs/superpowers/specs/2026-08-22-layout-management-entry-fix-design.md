# DashFlow 布局管理入口与快速记录修复设计

日期：2026-08-22

## 背景与根因

当前 DashFlow 已实现卡片添加、配置、拖动、调整尺寸和移除，但用户在“今天”和“工作台”页面都找不到进入布局编辑的入口。

根因不是功能缺失，而是展示层冲突：`DashboardRenderer` 创建的编辑按钮被 `ProductExperienceService` 移入 `.dashflow-section-title`，随后该标题容器又被产品样式永久隐藏。因此按钮存在于 DOM 中，却无法被用户看到。

快速记录弹窗还存在一处样式覆盖：新版目标行应位于输入框下方，但 `WorkflowStyles` 中遗留的负外边距覆盖了新版样式，使“更改目标”按钮向上挤压并与“保存”区域发生视觉重叠。

## 目标

- 在所有主要页面的顶部命令栏中提供稳定、可见的“布局”入口。
- 进入编辑状态后，让卡片的拖动、配置和移除操作无需猜测即可发现。
- 保留二次确认，避免误删卡片。
- 修正快速记录目标行的排版，使输入、保存、目标设置和更多创建方式形成清晰的纵向层级。
- 不改变任务、项目、笔记或习惯等业务数据。

## 非目标

- 不新增独立的组件管理页面。
- 不重写现有网格布局或组件注册系统。
- 不改变“添加”按钮和功能中心的业务含义。
- 不删除任何知识库内容或插件配置文件。

## 交互设计

### 顶部布局入口

在顶部命令栏右侧操作区中，将“布局”作为带文字的常驻按钮，位置靠近“功能”。按钮在“今天、工作台、收集箱、项目、日历、习惯、复盘”等主要页面都可见。

- 默认状态：显示“布局”，图标使用布局/面板语义。
- 点击后：进入统一布局编辑视图，恢复全部真实卡片并显示编辑控件。
- 编辑状态：按钮文案变为“完成”，并保持明显的激活状态。
- 点击“完成”：保存现有布局状态并返回进入编辑前所在的产品页面。

现有编辑按钮仍作为状态控制源，但不再被移动到隐藏的标题区域，而是由命令栏承载。

### 卡片编辑控件

编辑状态下，每张卡片标题栏右侧显示三个操作：

- 拖动：保留拖动手柄。
- 配置：打开该卡片配置。
- 移除：使用清楚的移除语义和可访问标签，不再只依赖难以理解的 `×`。

移除仍采用当前的限时二次确认：首次点击切换为“再次确认”，5 秒内再次点击才真正从当前工作台移除。移除只改变仪表盘卡片列表，不删除笔记、任务、项目或其他业务数据。

### 快速记录布局

快速记录保持 600px 最大宽度和现有功能，调整为稳定的四层结构：

1. 标题与说明。
2. 输入框及右侧“保存”按钮。
3. 独立的目标行：左侧显示当前写入目标，右侧显示“更改目标”。
4. “更多创建方式”及三个入口。

目标行不得使用负外边距，不得与输入框或保存按钮重叠。窄屏时目标行允许自然换行，操作按钮保持可点击。

## 错误处理与安全

- 如果目标卡片已经不存在，配置或移除请求直接忽略，不产生异常。
- 卡片移除继续走 `DashboardManager.removeWidget`，并同步清理移动端排序和折叠状态。
- 用户误移除后可在编辑栏重新添加同类型卡片。
- 不修改插件 `data.json` 的结构，不引入数据迁移。

## 验证标准

- 静态回归测试证明命令栏包含常驻布局按钮，且按钮复用真实编辑状态。
- 交互契约测试证明编辑状态下存在可识别的移除按钮和二次确认逻辑。
- 样式测试证明隐藏标题不再吞掉布局入口。
- 样式测试证明快速记录目标行不存在负外边距，并具备窄屏布局规则。
- 完整测试套件和生产构建通过。
- 构建产物复制到目标知识库后，源文件与安装文件哈希一致。
