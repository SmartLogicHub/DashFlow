# DashFlow 统一行动闭环与功能可发现性设计

## 状态

产品负责人已在 2026-08-22 确认按推荐方向继续。本规格是第一阶段实现边界，目标是先解决“功能已经存在，但用户看不见、找不到、页面可能为空”的问题；后续再迭代更强的过程引导和自动建议。

## 问题定义

DashFlow 已有 18 种 Widget、7 个固定导航分区、Obsidian 命令、设置项和若干联网集成，但当前产品壳层没有形成稳定闭环：

- 当前 Dashboard 只包含 11 种 Widget，其他能力只能在布局编辑器的下拉框中发现。
- 固定导航分区从当前 Dashboard 的 Widget 实例中筛选内容；精简模板可能让项目、日历、习惯或复盘页缺少主体内容。
- 项目看板和项目时间轴已经实现，但项目分区只允许普通项目列表。
- 情景切换、Dashboard 管理、新建项目、新建习惯和 AI 规划等入口被正常态样式隐藏。
- AI、晨间简报、微信读书等功能的“已启用 / 未启用 / 待配置”状态没有统一可见入口。

参考 `byoungd/up` 的不是其页面样式，而是它始终围绕“诊断 → 任务 → 行动 → 证据 → 复盘”组织内容。DashFlow 应把已有能力组织成“捕捉 → 整理 → 执行 → 跟踪 → 复盘”的可操作闭环。

## 方案比较

### A. 展开全部按钮

把所有 Widget、命令和集成都放进顶栏。实现简单，但会重新制造拥挤、响应式隐藏和概念竞争，不能解决固定页面内容依赖 Dashboard 的问题。

### B. 稳定分区 + 功能中心 + 上下文补齐（采用）

保留七个主分区和用户可配置 Work Dashboard，新增统一功能中心；每个固定分区声明自己拥有的能力，并在缺少对应 Widget 时显示可解释、可一键补齐的空状态。项目页同时接纳列表、看板和时间轴。该方案复用现有数据、Widget 和编辑器，改动可控，也能让每项功能有唯一可理解入口。

### C. 重写七个独立页面

让项目、日历、习惯和复盘全部脱离 Widget 系统，重新实现专用页面。长期边界最干净，但会复制现有渲染与交互逻辑，第一阶段风险和工作量过高。

## 产品结构

### 1. 主闭环

- **收集箱**：捕捉和整理未决事项。
- **今日**：显示当前重点和下一步，入口指向收集、执行和记录。
- **工作台**：承载用户选择的执行工具和高密度总览。
- **项目**：统一承载项目列表、项目看板和项目时间轴。
- **日历**：承载时间计划。
- **习惯**：承载长期节奏与活跃度。
- **复盘**：承载周复盘、活跃度和 Vault 统计。

主导航只表达这些阶段，不再承担所有功能入口。

### 2. 功能中心

顶栏新增一个始终可见的“功能”按钮，打开轻量功能中心。功能中心不是第二套设置页，而是产品能力目录：

- 按“捕捉与整理、执行、项目、回顾、智能与扩展”分组。
- 每项展示名称、简短用途、所属分区和状态。
- 状态至少区分：当前 Dashboard 已添加、尚未添加、已启用、需要配置。
- Widget 能力可一键添加到当前 Dashboard；添加后提示去所属分区或工作台查看。
- 命令型能力直接打开现有 Modal 或页面。
- 配置型能力打开 DashFlow 对应设置区，不复制配置表单。

功能目录由新的纯模块集中定义，导航、功能中心和测试都消费同一数据，避免入口字符串散落。

功能中心必须完整纳入以下用户能力：

- **全部 18 种 Widget**：快速捕捉、今日任务、任务概览、项目、即将到期、Weekly Review、日历、长期习惯、活跃度、倒计时、Vault Pulse、Visual Data Filter、Magic Embed、Focus、AI 早报、项目时间轴、项目看板、灵感收集。
- **创建与查找命令**：快速添加、新建任务、新建项目、新建习惯、全局搜索。
- **智能与阅读集成**：AI 规划、AI 晨间简报、微信读书。
- **工作台能力**：管理工作台和配置情景模式。

导出/导入 Dashboard JSON、重新索引 Vault、数据恢复和开发诊断属于高级维护操作，继续保留在设置或 Obsidian 命令面板，不进入日常功能中心。新增 Widget 或日常用户命令时，必须显式加入功能目录或在测试允许的维护操作清单中登记，不能静默遗漏。

状态不是一个互斥枚举，而是两个维度：

- **放置状态**：`added`、`not-added`、`not-applicable`。只有 Widget 使用前两项；命令和集成为 `not-applicable`。
- **可用状态**：`ready`、`disabled`、`needs-configuration`。本地 Widget 和普通命令通常为 `ready`；功能总开关关闭为 `disabled`；已启用但缺少凭据或必要配置为 `needs-configuration`；已配置但未启用仍显示 `disabled`，并保留“已配置”辅助说明。

界面可以同时显示两个状态，例如“未添加 · 可用”或“已添加 · 需要配置”，不能把“已添加”误当成“已可用”。

### 3. 分区所有权

新增集中式分区策略：

- `projects`：`projects`、`project-kanban`、`project-gantt`
- `calendar`：`calendar`
- `habits`：`habits`、`heatmap`
- `review`：`weekly-review`、`heatmap`、`vault-stats`
- `work`：当前 Dashboard 中所有未隐藏 Widget

Today 与 Inbox 继续使用现有专用页面。高级项目视图不再只混在 Work 中。

各固定分区的推荐基础 Widget 明确为：项目=`projects`，日历=`calendar`，习惯=`habits`，复盘=`weekly-review`。`heatmap` 同时出现在习惯和复盘分区，但在功能中心的主要归属为复盘；添加后提示去复盘查看，同时不阻止它在习惯页复用。

### 4. 上下文补齐

固定分区不得因为当前模板缺少 Widget 而呈现空白页面。若某分区没有任何所属 Widget：

- 显示该分区的真实用途和缺失原因。
- 提供一个主操作，添加推荐的基础 Widget。
- 项目页额外展示列表、看板、时间轴三个视图选项；未添加的视图显示“添加此视图”，已添加的视图可直接切换。
- 不在后台静默修改用户 Dashboard，也不强制让 Minimal 模板变得臃肿。

项目页一次只渲染一个项目视图，默认优先普通项目列表；用户切换到看板或时间轴后，选择只在当前 Obsidian 会话内保存在 `ProductExperienceService`，不写入 Dashboard schema。若同一类型存在多个实例，固定选择当前 Dashboard Widget 顺序中的第一个。选择未添加的视图时先显示说明与“添加此视图”；添加成功后立即切换到新实例。Work 仍按保存布局同时显示所有未隐藏实例，不受项目页单视图规则影响。

### 5. 隐藏入口的处理

- 保留 Quick Add 为统一创建入口。
- 新建任务、项目、习惯和 AI 规划进入功能中心，同时继续保留 Obsidian 命令。
- Dashboard 管理继续只在布局编辑时出现，但功能中心提供“管理工作台”入口，让用户无需猜测。
- 情景模式保留在设置中；在 Work/Review 情景尚未配置时不作为主导航显示。
- 窄屏可以隐藏文字，但不能隐藏功能中心图标和当前分区反馈。

## 代码边界

### 新增

- `src/product/featureCatalog.ts`：纯数据目录、状态计算所需类型、功能分组和目标分区。
- `src/product/sectionPolicy.ts`：分区拥有的 Widget 类型、推荐基础 Widget 和缺失状态计算。
- `src/ui/FeatureHubModal.ts`：渲染功能中心并调用现有添加、导航、命令和设置能力。
- `src/styles/FeatureHubStyles.ts`：功能中心、分区空状态和项目视图切换样式。

### 修改

- `ProductExperienceService`：增加功能按钮、消费分区策略、渲染上下文补齐与项目多视图。
- `DashboardManager`：复用现有 `addWidget`，不新增第二套持久化。
- `DesignSystemService`：注入新增样式模块。
- 相关设置/Modal 仅暴露已有打开方法；不复制业务逻辑。

## 数据与错误处理

- 不改变 Markdown 业务数据格式。
- 不改变 Dashboard schema；添加 Widget 仍使用现有持久化流程。
- 添加失败时保留当前界面并显示明确 Notice，不呈现假成功状态。
- 需要联网或凭据的能力在功能中心显示配置状态，未配置时不自动发起网络请求。
- 同一类型允许现有系统继续添加多个实例；功能中心的“已添加”表示至少存在一个实例。

## 测试策略

所有行为修改遵循测试先行：

1. 纯逻辑测试验证 18 种注册 Widget 均能映射到功能目录或明确标记为内部能力。
2. 分区策略测试验证项目页接纳列表、看板和时间轴。
3. 精简 Dashboard 测试验证固定分区得到可操作缺失状态，而不是空白。
4. 功能状态测试覆盖已添加、未添加、已启用和待配置。
   状态断言分别覆盖放置维度与可用维度，并包含“已配置但未启用”的集成。
5. 源码结构测试验证功能按钮在正常态与窄屏都不会被隐藏。
6. 运行完整测试、TypeScript 检查、生产构建和 `node --check main.js`。
7. 安装到测试 Vault 后人工检查桌面宽屏、窄屏、项目多视图、功能中心和一键补齐。

## 非目标

- 本阶段不重写现有 Widget 渲染器。
- 不自动创建示例任务、项目或习惯。
- 不强制把全部 18 种 Widget 加入默认工作台。
- 不引入新的数据库、前端框架或图标库。
- 不在本阶段实现基于行为的 AI 自动推荐。

## 验收标准

1. 用户能从正常界面发现全部 18 种 Widget 及主要命令/集成，不必先进入布局编辑模式。
2. Minimal 或其他精简模板下，项目、日历、习惯和复盘页不会无解释地空白。
3. 项目列表、项目看板和项目时间轴都在项目页有明确入口。
4. AI 规划、晨间简报、微信读书等能力显示真实启用/配置状态。
5. Work 继续展示当前 Dashboard 中所有未隐藏 Widget，用户布局与 Markdown 数据不受破坏。
6. 窄屏保留功能中心入口和可理解的当前页面状态。
7. 自动化检查与测试 Vault 视觉检查全部通过。

## 后续阶段

第二阶段再把闭环提示做深：为 Inbox 增加批量整理节奏，为 Today 增加“下一项最小行动”，为 Work 增加完成后的证据记录，为 Review 生成可写回 Markdown 的复盘结果。第一阶段先确保所有能力可发现、分区稳定、入口一致。
