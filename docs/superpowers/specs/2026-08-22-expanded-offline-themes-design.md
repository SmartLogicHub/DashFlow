# DashFlow 离线主题扩充设计

日期：2026-08-22

## 背景

DashFlow 当前提供 Alpine、Paper、Midnight 三个带图场景和一个跟随 Obsidian 的自适应主题。它们覆盖冷色明亮、暖色明亮和深色三种基础方向，但选择数量少，视觉个性不足，而且主题名称仍混用英文与中文。

本次扩充采用“完整主题”方案：每个主题同时定义 Hero 场景、本地离线图片、页面画布、卡片表面、文字层级、边框和强调色，而不是只替换背景图。

## 目标

- 新增 5 个彼此差异明显的完整主题，总数由 4 个增加到 9 个。
- 所有主题场景图都随插件离线打包，不依赖远程图片服务。
- 主题名称和说明统一使用中文，底层 ID 保持稳定，避免数据迁移。
- 主题选择区在宽屏、窄屏和 Obsidian 设置面板中保持清晰、不过度拥挤。
- 保留用户从 Vault 选择自定义 Hero 图片的能力；自定义图片继续优先于主题场景。

## 非目标

- 不把“场景图片”和“配色”拆成两个独立设置。
- 不改变 Obsidian 本身的主题或编辑器配色。
- 不增加在线下载主题、主题商店或第三方主题包。
- 不替换现有三张 Hero 图片。

## 主题目录

### 现有主题中文化

底层 ID 与资源路径不变，仅调整界面名称和说明：

- `alpine`：雪山冷蓝——清醒、专注的山谷晨光。
- `paper`：海岸晨光——柔和、留白的暖色海岸。
- `midnight`：雾林深夜——沉静、专注的深色森林。
- `obsidian`：跟随 Obsidian——使用当前 Obsidian 的颜色，不使用内置场景图。

### 新增完整主题

#### 森屿（`moss`）

- 场景：清晨薄雾中的苔绿森林与安静溪谷。
- 色彩：低饱和苔绿、灰绿画布、暖白卡片。
- 强调色：深松绿。
- 气质：自然、安静、适合长期阅读和知识整理。

#### 沙丘（`dune`）

- 场景：日出前后的柔光沙丘，纹理克制、留白充足。
- 色彩：陶土、沙金、米白与深棕。
- 强调色：赭石。
- 气质：温暖、沉稳、适合写作和项目规划。

#### 水墨（`ink`）

- 场景：层叠远山、雾气与水面构成的东方灰阶景观。
- 色彩：墨灰、宣纸白、冷中性灰。
- 强调色：克制的青灰。
- 气质：东方极简、留白、适合专注和复盘。

#### 樱雾（`blush`）

- 场景：清晨薄雾中的浅粉花野与柔和山影，不出现人物。
- 色彩：低饱和粉灰、暖白、梅子灰。
- 强调色：柔和莓红。
- 气质：轻盈、温柔，但保持工具产品的专业感。

#### 极光（`aurora`）

- 场景：深青夜空、远山和克制的青绿色极光。
- 色彩：深海军蓝、墨青、冷灰。
- 强调色：青绿。
- 气质：沉浸、科技感、适合夜间工作。

## 图片资产规范

每个新增主题生成一张独立横向 Hero 图片，使用 `imagegen` 内置模式。图片属于项目资产，最终必须复制到：

`assets/heroes/<theme-id>.webp`

统一要求：

- 宽幅自然风景构图，适合作为约 6:1 到 9:1 的横向 Hero 裁切来源。
- 主体细节集中在画面中部或右侧，左侧保留可读文字安全区。
- 低饱和、自然光、轻薄雾感，与现有三张照片保持同一产品世界。
- 无人物、无建筑主体、无文字、无标志、无水印、无夸张 HDR。
- 图片需检查裁切后文字对比度，并转换为体积适中的 WebP。

## 颜色系统

每个主题继续通过 `data-dashflow-theme` 设置 CSS 变量：

- `--df-home-canvas`
- `--df-home-surface`
- `--df-home-surface-2`
- `--df-home-border`
- `--df-home-border-strong`
- `--df-home-text`
- `--df-home-muted`
- `--df-home-faint`
- `--df-home-accent`
- `--df-home-accent-soft`
- `--df-home-reading`
- `--df-home-reading-2`
- `--df-home-scene`
- 对应的 `--df-cmd-*` 命令栏变量

亮色主题必须维持清晰正文对比度；`aurora` 使用完整深色表面，不依赖 Obsidian 当前明暗模式。主题切换只影响 DashFlow 容器。

## 主题选择器

- 使用现有图片卡片交互和保存失败回滚逻辑。
- 宽屏采用三列卡片，避免当前四列造成标题和说明拥挤。
- 中等宽度采用两列，窄屏采用单列。
- 当前主题继续显示明确状态；键盘焦点、悬停和按下反馈保留。
- 自定义 Hero 图片存在时，在选择区说明“配色已切换，图片仍使用自定义 Hero”，避免用户误以为主题无效。

## 数据兼容与错误处理

- 扩展 `HomeTheme` 联合类型，但不提升 schema 版本，不迁移旧数据。
- 现有 `alpine`、`paper`、`midnight`、`obsidian` 值保持有效。
- 主题保存失败时继续回滚到此前主题。
- 缺少或无法解析本地图片时，使用该主题的 CSS 渐变回退，不阻塞页面渲染。
- 主题切换不改 `homeHeroImagePath`；用户清除自定义图片后才恢复内置场景。

## 验证标准

- 主题目录准确包含 9 个稳定 ID，其中 8 个带本地图片，`obsidian` 不带图片。
- 5 张新增图片都存在、可解码、为横向 WebP，并被构建与发布流程纳入。
- 每个新增主题都有完整 CSS 变量集与可读的亮/暗表面。
- 设置页主题卡在三列、两列和一列布局下均不裁切标题与说明。
- 旧主题持久化和失败回滚测试继续通过。
- 完整测试、生产构建和安装哈希核对通过。
