# DashFlow 0.7 渐进式表现层重建设计

日期：2026-08-22  
状态：待实施  
目标版本：0.7.0

## 1. 背景与目标

DashFlow 已经具备完整的个人生产力数据链路、255 项自动测试、严格 TypeScript、恢复机制、SecretStorage、CI 与 Release 工作流。当前主要问题不在业务能力，而在表现层经过多轮迭代后形成的样式叠加、过小字体、窄窗功能入口不可见、固定高度与嵌套滚动、空状态空间利用不足，以及版本发布治理滞后。

本次选择“渐进式表现层重建”：保留已经稳定的数据与业务层，按页面逐步迁移到一个可维护的视觉系统，完成一页、验证一页，最后删除被替代的旧样式。禁止通过新增一层全局覆盖 CSS 来掩盖旧问题。

成功标准：DashFlow 在宽屏、分栏窄窗与移动尺寸下都保持关键入口可见、文字可读、页面无意外嵌套滚动；视觉规则只有明确所有者；版本、文档与发布产物保持一致。

## 2. 范围边界

### 保持不变

- Markdown 仍是任务、项目、习惯和机会数据的事实来源。
- `VaultIndexService`、查询缓存、任务/项目/习惯服务及其数据模型不重写。
- Dashboard 配置、Widget ID、用户布局、移动顺序和现有迁移数据保持兼容。
- AI、微信读书、Morning Briefing、SecretStorage 和网络安全边界保持不变。
- 已有命令 ID、设置数据字段和主要用户工作流保持兼容。
- 不引入新的前端框架、图标库或远程字体。

### 本次重建

- 设计令牌、排版比例、表面层级、响应式规则和交互尺寸。
- 顶部导航与动作区在窄内容区的布局和可发现性。
- 工作台、项目、日历、习惯、复盘页面的内容编排与空状态。
- 功能中心的搜索、状态筛选、滚动边界与移动布局。
- 设置页的卡片排版、文本截断和控件对齐。
- 与上述页面相关的旧样式清理、样式所有权和回归测试。
- 0.7.0 版本、CHANGELOG、README、versions.json 与 Release 校验。

### 暂不决定

- 仓库许可证属于所有者的法律选择。本次只保留明确的发布阻塞说明，不擅自添加 MIT、GPL 或专有许可证。

## 3. 设计原则

1. **业务稳定优先**：表现层可以替换，数据语义和持久化协议不能漂移。
2. **一个规则一个所有者**：基础令牌、页面几何、组件外观、动效和功能专属样式不得重复定义同一属性。
3. **容器优先响应式**：DashFlow 经常运行在 Obsidian 分栏中，布局以实际内容区宽度为依据，不能只看浏览器视口宽度。
4. **可读性优先于密度**：常规辅助文字不得低于 11px，正文不得低于 12px；仅非关键装饰刻度允许更小且不得承载唯一信息。
5. **减少滚动上下文**：页面滚动为主；卡片内部滚动仅用于明确的数据表格或用户主动展开的区域。
6. **空状态推动下一步**：空状态必须解释原因并提供一个主操作，不用大面积空白表达“没有数据”。
7. **遵循 Obsidian**：继承 Obsidian 字体和主题变量，不使用破坏主题兼容性的强制品牌字体。

## 4. 表现层架构

### 4.1 样式层级

新的设计系统按以下顺序组织，使用清晰的 CSS layer 或等价的确定性注入顺序：

1. `tokens`：颜色、字体、间距、圆角、阴影、控件高度、动效时间。
2. `foundation`：DashFlow 根容器、语义排版、焦点、减少动画和基础表面。
3. `shell`：Hero、主导航、Dashboard 画布和页面容器。
4. `components`：Widget、行项目、状态标签、空状态、按钮和表单。
5. `features`：日历、复盘、功能中心、Focus 等特定模块。

迁移期间允许旧模块存在，但新旧规则不能同时拥有同一个核心几何属性。每完成一个页面，就删除该页面对应的旧覆盖规则。最终不再使用“最终修补层”覆盖前面的设计层。

### 4.2 排版系统

- 页面展示标题：28–32px，紧凑行高与负字距。
- 工作页 Hero 标题：24–28px。
- 组件标题：14px，650–700。
- 正文：13px，行高 1.5–1.6。
- 次级文字：12px。
- 标签、状态和时间：最低 11px。
- 数据数字统一启用 `tabular-nums`。
- 中文是主界面语言；保留必要产品名，统计标签和状态说明优先中文化。

### 4.3 响应式导航

宽内容区维持单行导航。进入窄内容区后，命令条切换为两层：

- 第一层是可横向滚动的页面导航，当前页面自动滚动到可见区域，并显示边缘渐隐提示。
- 第二层是固定动作区，仅保留“添加”“功能”“搜索”；“功能”保留文字标签并始终位于可视范围。
- Dashboard 管理和次要创建动作不占用窄屏常驻空间，仍可从功能中心进入。
- 触控目标最低 36px；日历单元格在移动布局中以可用宽度填充，不保留 17–20px 的点击区域。

验收尺寸至少包括：1160px 内容区、820px 应用窗口、700px 应用窗口，以及约 360–430px 的移动内容区。

## 5. 页面设计

### 5.1 今日

保留现有沉浸式 Hero 和“今天—今日状态—长期成长—最近记录”叙事。减少不必要的大写英文标签，保持今日页作为视觉基准。所有交互卡片提供清晰 hover、active 和 focus 状态。

### 5.2 工作台

维持高密度执行视图，但去除卡片内无提示滚动：

- 项目卡在工作台只显示有限的高优先级/活跃项目，并提供“查看全部项目”。
- Weekly Review 在工作台显示摘要而不是完整三栏报告；完整内容留在复盘页。
- 可增长内容优先增高或截取摘要，不在 176px 固定卡片中塞入完整列表。
- 任务概览继续采用“今日为主、全部为辅”的结构。

### 5.3 项目

列表、看板、时间轴继续共用一个页面切换器。列表卡片根据内容自然高度排列；缺少看板或时间轴时提供一键加入。无项目时显示紧凑引导，主操作是“创建第一个项目”，次操作是“从模板开始”。

### 5.4 日历

保留月视图和右侧当天详情。星期、日期和事件文字提升至可读下限；移动端将详情移动到日历下方。日期点击区域随网格单元格展开，不能缩成细小文本按钮。

### 5.5 习惯

有数据时保留习惯列表与活跃度组合；无数据时将习惯卡改为紧凑引导，提供“创建第一个习惯”，活跃度说明数据何时开始积累。避免左侧大块空白只放一句提示。

### 5.6 复盘

完整 Weekly Review 只在复盘页展示。提高 KPI、分组标题、状态和元数据字号；内容按页面自然增长，不把三栏内容塞进固定高度滚动卡。窄屏依次排列“本周概览—需要处理—项目—习惯/日更—下周关注”。

### 5.7 功能中心

保留 28 项 canonical catalog，并增加：

- 搜索名称与说明。
- “全部 / 未添加 / 待配置”状态筛选。
- 无匹配结果提示和清除筛选动作。
- 弹窗高度受视口约束，内容区独立滚动，标题与搜索区保持可见。
- 窄屏单列；宽屏双列。
- 状态由已有 `featureStatus` 计算，不建立第二套功能状态。

### 5.8 设置

保留四个设置分区。主题卡图片、标题、说明和状态标签采用稳定网格；长文本允许两行，不以固定按钮高度裁掉说明。设置页滚动只发生在 Obsidian 的设置内容区。

## 6. 状态、错误与无障碍

- 所有图标按钮必须有可访问名称。
- 当前主导航和项目视图使用 `aria-current="page"`。
- 筛选按钮使用 `aria-pressed`，搜索输入具有明确标签。
- 键盘可以进入功能中心、切换筛选、打开功能并关闭弹窗。
- 保留 `prefers-reduced-motion`，只对 `transform` 和 `opacity` 使用动效。
- 网络、保存和 Widget 添加失败继续使用明确的 Obsidian Notice，不静默失败。
- 空状态主操作失败时不得隐藏原始状态或丢失用户数据。

## 7. 测试策略

采用测试驱动迁移：每项行为修改先写失败测试，再写最小实现。

### 自动测试

- 纯逻辑测试：功能搜索与筛选、工作台摘要选择、响应式可见动作策略。
- 结构测试：设计令牌、样式所有权、字号下限、容器响应式规则和发布元数据一致性。
- 现有 255 项测试必须全部保留通过。
- 增加版本与 Release 校验，避免相同版本发布被静默跳过。

### 真实 Obsidian 验收

- 七个主页面、功能中心和四个设置分区无控制台错误。
- 宽屏与 820/700px 分栏尺寸下，“功能”均在视口内。
- 移动尺寸功能中心为单列，页面无意外横向溢出。
- 工作台项目和复盘页不再出现固定高度内容裁切。
- 文字抽样不存在承载业务信息的 7–10px 文本。
- 浅色、深色及“跟随 Obsidian”主题至少各验证一次。

## 8. 发布治理

- 版本升级至 0.7.0，并同步 `package.json`、`package-lock.json`、`manifest.json` 和 `versions.json`。
- CHANGELOG 增加 0.7.0 的用户可见变更、升级说明和兼容边界。
- README 更新功能中心、窄屏行为、主题与数据安全说明。
- Release 工作流在发布前验证版本文件一致；同版本 Release 已存在时应失败并提示升级版本，不能静默跳过。
- CI 继续构建安装包并验证 `main.js`、`manifest.json`、`styles.css` 和本地 Hero 图片。
- GitHub 推送仍需用户单独确认。
